## ВАЖНЫЕ ГОТЧИ (грабли, на которые уже наступали)

- **SSH-соединение к обоим серверам периодически нестабильно** (ConnectionReset/timeout на ровном
  месте, особенно на длинных командах). Причина не выяснена. Решение: просто повторить команду
  1-3 раза, обычно проходит.
- **`pkill -f 'паттерн'` в той же SSH-команде, что и другие упоминания этого паттерна** — убивает
  СВОЙ ЖЕ процесс (pkill matches по всей cmdline, включая текст самой bash-команды). Решение:
  killing и launch — ВСЕГДА раздельные ssh-вызовы, паттерн для kill — `pkill -f '[r]enpy'`
  (self-exclusion trick через character class).
- **Ren'Py иногда игнорирует SIGTERM** в headless-режиме — если процесс не умер после pkill,
  добивать `kill -9 <pid>`.
- **ПРОВЕРЯТЬ `ps aux | grep renpy` перед тем как надолго уйти в фон/переключиться на другую
  задачу.** Один раз накопилось 9 забытых процессов от старых warp-тестов, съедали весь CPU
  (load average 25-28 на 4-ядерном VPS) и почти застопорили установку Android SDK на много часов.
  Убивать все ненужные перед началом нового долгого фонового процесса.
- **grep с `[а-яё]` диапазонами не работает** на сервере `dbugger` (invalid collation character,
  проблема с локалью). Для поиска по кириллице использовать `python3 -c "import re; ..."` вместо grep.
- **Прямой доступ на renpy.org (и похожие "нишевые" сайты) заблокирован с этой машины (bot-vm)**,
  но открыт с VPS `dbugger`. Используем VPS как relay: скачать на VPS → scp сюда, если нужно.
- **Ren'Py-порт ComfyUI (8188) закрыт наружу**, слушает только 127.0.0.1 на `gitverse-srv`.
  Для просмотра из браузера пользователю: `ssh -L 8188:localhost:8188 pr0100@192.168.127.242`
  (у пользователя нет алиаса gitverse-srv, только у меня — использовать IP напрямую в инструкциях ему).
- **SendUserFile не всегда видно пользователю** (зависит от того, какую панель VS Code он смотрит —
  иногда попадает в лог инструментов, а не в чат). Надёжный фолбэк: копировать файл в
  `~/Desktop/dbugger-renders/` на bot-vm — пользователь открывает через проводник.

## Игра — квест "dbugger", Эпизод 1 «Пробуждение станции»

- Формат: анимешная визуальная новелла, движок **Ren'Py 8.5.3**.
- Расположение: **на сервере `dbugger`**, путь `/root/dbugger-quest` (НЕ на этой машине).
  SDK там же: `/root/renpy-8.5.3-sdk`.
- **Git**: репозиторий инициализирован и запушен в приватный
  https://github.com/pr0100noob/dbugger-quest (main ветка). Пуш с VPS идёт через SSH deploy key
  `~/.ssh/id_ed25519_github_dbugger_quest` на самом VPS (настроен `~/.ssh/config` на VPS с алиасом
  `github.com` → этот ключ). Если нужно закоммитить новые правки — `cd /root/dbugger-quest &&
  git add -A && git commit -m "..." && git push` прямо на VPS по SSH.
- Персонаж ИИ: **Дебби** (была "Спарк", переименована — на артах читается как девочка, все родовые
  окончания в тексте поправлены, и у самой Дебби, и у игрока).
- **Сюжет — 5 комнат**, каждая учит одному "багу" использования ИИ:
  1. Входной зал — готовый ответ vs понимание (пример 24×17, показываются два способа решения,
     сначала демонстрация "как обычно спрашивают" через стилизованное чат-сообщение)
  2. Мастерская — расплывчатая просьба vs чёткая (шутка про розовый чайник)
  3. Архив — слепое доверие ИИ vs проверка фактов (несовпадение дат/цифр)
  4. Мастерская идей — ИИ как соавтор vs замена творчества (игрок выбирает имя ядра станции из
     вариантов, которые предлагает Дебби)
  5. Пульт управления — финал, рекап всех 4 уроков, значок "Дебаггер 1 уровня", тизер эпизода 2
- **Педагогическая петля** в каждой из 4 обучающих комнат: вступление/контекст → первая попытка
  игрока → если ошибся, Дебби объясняет и показывает пример → даёт ОДНУ повторную попытку →
  если получилось — успех; если снова нет — тёплая поддержка без стыда, мягкий переход дальше
  (никогда не зацикливается больше одного повтора).
- **Система профилей/регистрации** (для нескольких игроков на одном устройстве — обе дочери):
  - `label start` → если есть сохранённые профили — экран выбора (`select_profile`), иначе сразу
    создание нового (`new_profile`)
  - Новый профиль: имя (`renpy.input`), пол (влияет на грамматику через хелпер `g('муж','жен')`),
    возраст (влияет на тон через `is_young = age < 12`)
  - Данные хранятся в `persistent.profiles` (словарь: имя → {gender, age}), переживают перезапуск
  - Реальная механика: `[player_name]` подставляется в ключевые реплики каждой комнаты (не в
    каждой строке), `[g('...','...')]` — везде где нужно согласование рода у игрока/у Дебби,
    `if is_young:` — минимум 2 места с разным тоном (интро + кульминация финала), паттерн готов
    расширять дальше
  - **Склонение имени по падежам** — библиотека **petrovich** (чистый Python, вшита в
    `game/petrovich/`, переживёт сборку APK) — `decline_name(name, Case.DATIVE, gender)`.
    Пока не понадобилась в тексте (все вставки в именительном падеже), но готова на будущее.
- Проверено: lint чист (10 меню, 95 диалоговых блоков), несколько скриншотов через headless-пайплайн

## Сборка APK — В ПРОЦЕССЕ (не завершено на момент записи)

Цель: собрать `.apk` из `/root/dbugger-quest` и положить на сайт (кнопка уже готова, см. выше).

**Как это работает headless** (важное открытие этой сессии): RAPT (Ren'Py Android Packaging Tool)
обычно ставится и используется только через GUI лаунчера. Но у Ren'Py есть механизм регистрации
собственных CLI-команд (`renpy.arguments.register_command`), которым пользуется встроенная команда
`android_build`. Я зарегистрировал СВОЮ команду `setup_android` в файле
`/root/renpy-8.5.3-sdk/launcher/game/zz_headless_setup.rpy` (временный файл, не относится к
самому проекту игры, живёт в SDK лаунчера), которая:
1. Скачивает RAPT через `add_dlc("rapt", restart=False)` (та же функция, что дёргает кнопка в GUI,
   но с `confirm=False` — не требует диалогов).
2. Ставит Android SDK через `rapt.install_sdk.install_sdk(rapt.interface.Interface())`.

Команда запускается так: `cd /root/renpy-8.5.3-sdk && ./renpy.sh launcher setup_android`.

**Статус на момент записи**: команда запущена в фоне на VPS `dbugger`, лог — `/tmp/setup_android.log`
на VPS. Застряла на шаге "Downloading RAPT" на много часов из-за забытых зомби-процессов (см. готчи
выше, CPU был забит на 100% восемью старыми renpy-процессами) — процессы убиты, должна пойти
быстрее. **Проверить в новой сессии**: `ssh dbugger "cat /tmp/setup_android.log"` — если видно
"=== DONE ===", шаг 1-2 завершены успешно, идти дальше по плану ниже. Если всё ещё "Downloading
RAPT" и прошло много времени — что-то не так, разбираться (проверить `ps aux | grep renpy` на
зомби-процессы первым делом, проверить `curl -v https://www.renpy.org` с VPS на доступность апдейт-
сервера).

**Что делать дальше после того, как setup_android завершится (=== DONE ===):**
1. Проверить, что реально появилось: `ls /root/renpy-8.5.3-sdk/rapt/` (должна быть непустая папка)
   и путь к adb/sdk внутри (что скажет `rapt.plat.adb` — можно добавить ещё print в скрипт).
2. Сгенерировать ключи подписи: нужен аналогичный headless-вызов `rapt.keys.generate_keys(interface,
   "/root/dbugger-quest")` — я НЕ УСПЕЛ дописать эту команду в `zz_headless_setup.rpy`, нужно
   добавить как следующий шаг той же командой или новой (`setup_android_keys`).
3. Настроить `android.json` в `/root/dbugger-quest/` — файл уже существует (скопировался из
   шаблона the_question при копировании проекта), но содержит настройки ПРИМЕРА (не наши: имя
   приложения, package identifier "ru.dbugger.quest" или похожий, версия, permissions). Нужно
   открыть и поправить вручную (`cat android.json`) ИЛИ вызвать `rapt.configure.configure(...)`
   headless — сигнатуру этой функции ещё не проверял, смотри
   `/root/renpy-8.5.3-sdk/rapt/buildlib/rapt/configure.py` после того, как rapt скачается.
4. Собрать сам APK — команда УЖЕ ГОТОВА и проверена синтаксически (просто не хватало RAPT):
   `cd /root/renpy-8.5.3-sdk && ./renpy.sh launcher android_build /root/dbugger-quest`
   (без `--bundle` — получится Universal APK, то что нужно для прямого скачивания с сайта).
5. Готовый файл появится в `/root/dbugger-quest/bin/` (или похожем, смотри `rapt.plat.path("bin")`
   в выводе). Скачать на bot-vm через scp, залить в `C:\Users\fomichev\dbugger-ru\downloads\
   dbugger-quest.apk`, закоммитить и запушить сайт (git add/commit/push в `dbugger-ru`, обычный
   HTTPS remote, кэш кредов уже есть на этой машине).
